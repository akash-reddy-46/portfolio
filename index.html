How I work

Ship carefully, own the outcome.

How I actually operate day to day — the habits that keep revenue-critical services boring, and make my work easy for the next engineer to pick up.

Spec before code. I write the API contract and data model first and agree it with whoever depends on it — finance, ops, product or legal. Most of the expensive bugs I’ve seen were disagreements about meaning, not broken syntax.

Never test in production. I run changes locally against a local database or a staging stack before they touch a live system, and I clean up after myself when a test does leave a trace. Money, legal documents and customer messages don’t get a “let’s see what happens”.

Security is part of the definition of done. I’ve run security passes over my own work — closing SQL injection and auth holes, adding webhook signature verification, and rotating exposed credentials as part of a migration rather than as a follow-up ticket.

Small, readable commits. Scoped conventional commits (feat(crm): …), one logical change each, so history stays reviewable and a bad change is one revert away instead of an archaeology project.

Write it down. Every codebase I own carries its own README, architecture notes, deployment guide and changelog. If I disappeared for a month the team could still ship — that’s the bar I hold myself to.

AI as leverage, not autopilot. I use AI for the boring 70% — scaffolds, boilerplate, test cases, log spelunking. I keep the parts that don’t delegate well: API contracts, data modeling, idempotency, threat modeling and incident response. Every AI-assisted change clears the same review bar as code I write by hand.

Payments & Reconciliation Platform

JaaGa.AI · Cashfree · UPI collection · Idempotent retries · Webhooks
  • Problem Legacy billing was losing payments to flaky gateway responses and missing webhooks — a 2.8% failure rate on real money, and no clean way to collect over UPI without manual follow-up.
  • Approach Built an idempotent retry layer with exponential backoff, signed-webhook verification, dead-letter handling and a daily reconciliation job against Cashfree’s settlement API — plus a second rail that issues UPI payment requests as QR / VPA links, with an admin confirmation step against the customer’s payment screenshot. Dedicated payment API, processor and queue consumer so money never rides on a single request.
  • Impact Failure rate dropped to 0.3%, ₹50L+ monthly volume processed cleanly, and finance closes books a full day earlier.
Node.js Cashfree API UPI / VPA MongoDB AWS SQS Webhooks Slack / Teams

  • Impact One system of record for the sales floor: every lead is assigned and aged, every lost deal has a reason, and managers get printable team-performance and revenue reports instead of asking around.

AI Document Intelligence Pipeline

JaaGa.AI · OCR · Gemini · AWS Lambda · Templating
  • Problem Legal and property documents arrived as scans. Staff were manually reading, naming, indexing and re-typing 500+ documents a month into agreements, leases and ownership records — slow, and a copy-paste error away from a bad contract.
  • Approach Built an event-driven ingest pipeline: S3 upload → OCR → a dedicated AI document processor that uses Gemini to pull structured fields out of the raw text → validated MongoDB record. Generation runs off versioned docxtemplater templates with the extracted data, and queue workers own retries, so a bad scan never blocks the batch.
  • Impact 75% less manual effort with 99.2% OCR accuracy, document creation time down 80%, and zero data-loss incidents in 12 months of operation.
Node.js Google Gemini Vertex AI Tesseract OCR AWS Lambda S3 docxtemplater

Notification & Campaign Platform

JaaGa.AI · FCM broadcast · A/B/C testing · Queue workers
  • Problem Transactional messages were scattered across services with inconsistent delivery, and marketing had no way to push a broadcast to the app audience or learn which message actually worked.
  • Approach Built one notification consumer that fans a single event out to push, WhatsApp, email and internal channels with rate-limiting and retry on transient failure — then layered a Notification Campaigns module on top: audience selection, A/B/C variant testing with aggregate delivery/open counters, and scheduled sends, all driven from the admin console.
  • Impact Sustained 98.5% delivery at peak load, ~70% fewer manual steps in cross-team workflows, and one auditable place to answer “who got notified, when, and which variant won”.
Node.js Firebase FCM AWS SQS WhatsApp API AWS SES React

Crowd Data & Property Intelligence

JaaGa.AI · Crowd-sourced records · ETL · Verification
  • Problem Property intelligence depended on manual data pulls with no history, no alerting and no defence against the same document being uploaded twice by two different contributors.
  • Approach Built a fault-tolerant scrape → clean → store pipeline with queue-managed workers, schema validation on ingest and health alerts, plus a crowd-upload workflow in the admin console: allow-listed uploader access, match-criteria duplicate detection with the matched fields surfaced to the reviewer, document preview, “certified true” marking and admin audit stamps on every edit.
  • Impact Replaced a 4 hr/day manual job with an automated pipeline and gave the team a queryable, de-duplicated data layer with trend charts behind the property intelligence product.
